# MechrevoMode

机械革命模式便捷切换托盘工具 —— 常驻托盘，右键切档位，鼠标悬停看功耗/温度墙和两个风扇转速。

纯 Go 写的单文件小程序（无运行时依赖、无安装包）。不依赖任何第三方控制台，
直接对接机械革命自带的 **GCU** 后台服务，用官方那套本机 MQTT 协议读状态、下命令。

```
托盘图标：圆角正方形底色 + 白色字母（颜色和字母都能在界面上改）
左键单击/双击 → 打开设置界面
右键           → 档位菜单（带勾 = 当前档位）
鼠标悬停       → CPU 🌡85℃ ⚡38/38/45W
                 GPU 🌡87℃ ⚡50W
                 CPU 🌀2700RPM
                 GPU 🌀2598RPM
```

---

## 为什么需要它

官方控制台（以及第三方控制台 L-Mechrevo 之类）都要开一个大窗口才能换个模式，
而且不少机型上还常驻一堆用不到的东西。这个工具只做一件事：**把切模式变成两次点击**。
另外它把「模式 → 电源计划」的联动也一起做了 —— 这一点官方控制台不管。

## 功能

### 托盘

- **右键菜单**：只列你在界面上勾了「显示」的档位，当前档位带勾。菜单里没有别的项，
  也不放灰色信息行 —— 温度和功耗墙由悬浮提示承载，菜单只保留「动作」。
- **悬浮提示**：四行，每项前面带图标，**不用 `-` 分隔**：
  `CPU 🌡85℃ ⚡38/38/45W` / `GPU 🌡87℃ ⚡50W` / `CPU 🌀2700RPM` / `GPU 🌀2598RPM`。
  整块跟着档位和转速实时变化，**2 秒**重绘一次（与 GCU 遥测的推送节拍对齐，只有文本
  真变了才通知 Shell，所以不会闪）。不显示模式名（图标已经说明了）；GCU 没连上时
  退化成 `未连接`，转速拿不到时那一格显示 `--`。
- **图标怎么选的**：🌡 温度、⚡ 功耗、🌀 风扇。温度单位用单码位的 `℃`（U+2103）而不是
  `°C` 两个字符。这几个字符**实测能在提示字体（Microsoft YaHei UI）下渲染出真实字形**，
  不是豆腐块 —— 用 GDI 拿同一个字体把字符画进 DIB、再和「确定不存在的码位」比像素
  验过（`_research/_emoji_render_check.py`）。🌡 与 🌀 是星平面字符，在 UTF-16 里各占
  **2 个码元**，所以按字数估 `szTip` 容量会低估一半（`TestTipEmojiBudget` 钉住这件事）。
- **转速的来源**：只有 GCU 的 `System/FanInfo` 这一条路。笔记本上 NVML 不支持风扇
  （`GetNumFans` 返回 0），GCU 自己也是读 EC 得到 `CpuFanRpm` / `GpuFanRpm` 的。
  温度/功耗不显示 —— GCU 的 MQTT 侧压根没有整机功耗字段（挖遍全部 42 个主题常量
  都没有），而芯片温度用户明确不需要。
- **左键单击 / 双击**：立刻打开设置界面（实测 5.5 ms）。
  *注：曾做过「单击弹菜单 + 双击开界面」，因为单击必须先等满系统双击判定窗口（500 ms）
  才能确定不是双击，实测迟钝得没法用，已改回现在这样。*
- **图标**：圆角正方形底 + 白色字母。5×7 点阵字模，颜色和字母逐档位可配。
  生成尺寸取系统的 `SM_CXSMICON`（跟着 DPI 走，钳在 16–64，本机是 24），
  边缘做 4×4 超采样抗锯齿 —— 各尺寸下的效果在 `-dump-icons` 里从 16px 到 48px 都查过。

### 设置界面

一张模式表，八行（3 个内置档位 + 5 个自定义档位）：

| 列 | 说明 |
| --- | --- |
| 显示 | 是否出现在托盘右键菜单 |
| 模式名称 | 随便改，可带 emoji |
| 原始模式 | **只读**。这行到底对应哪个硬件档位（办公 / 均衡 / 狂暴 / 自定义 · 档位 N）。名称改乱之后靠它认路 |
| 图标 | 白色字母，单字符 |
| 底色 | 点开取色，或直接填十六进制 |
| 电源计划 | 节能 / 平衡 / 高性能 / 卓越性能 |

下面是**启动命令**区块：程序启动后延迟 N 秒执行一次命令（典型用途是 `ryzenadj` 降压）。
可选「需要管理员权限」，另有「立即运行」按钮方便试。输出不打印，成功失败看状态栏和气泡。

顶部两个开关：

- **开机自启动** —— 需要提权时写登录计划任务（`RunLevel=HighestAvailable`，登录后延迟 10 秒），
  否则写注册表 Run 项。原因见下方「已知限制」。
- **以管理员身份运行** —— 写当前用户的兼容性标志（`HKCU\...\AppCompatFlags\Layers` 的 `RUNASADMIN`），
  和你在资源管理器里勾「属性 → 兼容性 → 以管理员身份运行此程序」是同一处，随时能自己撤掉。

底部：恢复默认外观 / 保存设置 / 退出程序。

## 工作原理

GCU 后台一共**两个**组件，缺一不可：

| 组件 | 形态 | 作用 |
| --- | --- | --- |
| `GCUBridge` | Windows 服务 | 内嵌 MQTT broker，监听 `127.0.0.1:13688` |
| `GCUService.exe` | 普通进程 | 真正发布状态、执行命令的那个 |

本工具作为 MQTT 客户端接入（凭据是官方协议里固定的那套 `UWPClient_*`）：

```
订阅  Fan/Status       拿温度墙、SPL/SPPT/FPPT、GPU 功耗
订阅  Tray/Status      拿当前模式与档位
订阅  System/FanInfo   拿两个风扇的转速（悬浮提示用）
发布  Fan/Control      OPERATING_OFFICE_MODE / _GAMING_ / _TURBO_ / _CUSTOM_
```

`System/FanInfo` 每 2 秒推一条 `{"CpuFanRpm":2990,"GpuFanRpm":2854,…}`。
注意 GCU 在这一块**写法不统一**：同一次推送里 `CpuTemperature` 是字符串 `"63"`，
而 `CpuFanRpm` 是原生数字 —— 两种都得能解析（见 `gcuNum`）。
其余三十来个主题（`System/Control`、`Monitor/Status`…）订阅了也一条都不来，所以不订。

两个细节值得一提：

- **档位落定期**。GCU 切换过程中会先回几条旧状态，照单全收的话档位会被冲回上一个值。
  所以下发后有一段落定期，期间只接受与目标 `mode+slot` 完全一致的回报。
- **后端自愈**。`GCUBridge` 开机时会自己异常终止（系统日志事件 7023），
  而服务上**没有**配置恢复动作 —— 于是端口无人监听、永远连不上，
  直到你手动打开一次官方控制台。本工具会检测并主动把后端拉起来
  （间隔 40 秒、留足冷启动宽限期，不会催得过急）。

## 环境要求

- Windows 10 / 11
- **已安装机械革命官方控制中心**（提供 `GCUBridge` 服务与 `GCUService.exe`）。
  不要求它正在运行，但文件得在 —— 本工具靠它们连 GCU。
- 首次运行会自己探测 MQTT 客户端序号（`client_index`，-1 = 自动）。

## 使用

1. 把 `MechrevoMode.exe` 放到任意目录，双击运行。
2. 第一次运行会自动打开设置界面，按需改档位名称、图标、电源计划，点保存。
3. 勾上「开机自启动」和（需要的话）「以管理员身份运行」。

### 数据文件

数据目录优先放在**程序同目录的 `data\`**（绿色布局）；该目录写不进去（比如装在
`Program Files`）时自动回退 `%APPDATA%\MechrevoMode`，启动日志里会写明用的是哪个、为什么。
旧位置的 `config.json` 会在首次启动时自动迁移过来，并改名成 `config.json.migrated` 留底。

```
data\
  config.json            设置（模式表、启动命令、开关）
  log.txt                运行日志。排查问题先看这个
  icons\sheet.png        -dump-icons 生成的图标自检图
  autostart_task.xml     开机自启计划任务的临时定义
```

## 命令行参数

都是自检 / 调试用的，跑完就退出，不影响正在运行的实例。

| 参数 | 作用 |
| --- | --- |
| `-show` / `--show` | 启动后直接打开设置界面 |
| `-dump-gcu` | 只读打印 GCU 后端现状（服务状态、端口、进程） |
| `-dump-plans` | 导出电源计划枚举结果到 `data\plans.txt` |
| `-dump-icons` | 把托盘图标各尺寸渲染成对照图 `data\icons\sheet.png`，并打印字模留白余量 |
| `-test-plans` | 逐个试切内置电源方案，测完还原 |
| `-test-elevate` / `-test-elevate-off` | 写入 / 清除「以管理员身份运行」标志 |
| `-test-gcu-launch <exe>` | 验证「静默拉起进程」这条兜底路径 |
| `-switch <key>` | 启动后单次切到指定档位（key 见 `config.json`） |

## 从源码构建

```bash
go test ./...
go build -trimpath -ldflags "-s -w -H windowsgui" -o MechrevoMode.exe .
```

`-H windowsgui` 是必须的，否则会多出一个控制台窗口。注意这样构建出来的程序**没有 stdout**，
所有输出都进 `data\log.txt`。

依赖只有 `github.com/eclipse/paho.mqtt.golang`（MQTT 客户端），其余全是标准库 + `syscall`。
没有 cgo，产物就是单个 exe。

### 代码导读

| 文件 | 职责 |
| --- | --- |
| `main.go` | 窗口过程、托盘（图标 / 提示 / 菜单）、单实例互斥体、启动流程与自检分支 |
| `telemetry.go` | 悬浮提示的显示常量（🌡 ⚡ 🌀 ℃）、转速两行的排版与文本拼装 |
| `gcu.go` | GCU MQTT 客户端：连接与序号探测、状态解析、命令下发、后端自愈 |
| `config.go` | 配置结构与迁移、数据目录解析、开机自启（注册表 / 计划任务） |
| `ui.go` | 设置界面全部控件的创建与事件处理 |
| `power.go` | 电源计划枚举与切换（含「卓越性能」的按需复制与 GUID 固定） |
| `elevate.go` | 「以管理员身份运行」的兼容性标志读写、提权重启 |
| `icon.go` | 托盘图标位图生成（圆角正方形 + 5×7 点阵字模 + 超采样抗锯齿） |
| `icon_dump.go` | 图标自检图 |

`_research/` 是开发期的探测脚本（Python + ctypes），用来验证界面交互、托盘行为、
MQTT 报文格式等。不参与构建，但排查问题时很好用。

## 已知限制 / 注意事项

- **别放在云同步目录**。OneDrive 之类的「按需下载」会把 exe 变成云端占位文件，
  登录自启时就拉不起来了 —— 而且是**静默失败**，没有任何报错。程序启动时如果发现自己在
  同步目录里，会在日志里提醒一句。
- **「以管理员身份运行」+ 开机自启 = 计划任务**。Windows 在设计上就不会把
  注册表 Run 项 / 启动文件夹里的项提权拉起（这类条目会被静默跳过，任务管理器里还显示
  「已启用」）。所以登录时想跑一个需要管理员权限的常驻程序，只能用计划任务的
  `RunLevel=HighestAvailable`。副作用是「任务管理器 → 启动」里看不到本程序，
  这是正常的；界面的保存反馈里会把实际采用的机制写出来。
- **UAC 提示**。勾了「以管理员身份运行」且系统 UAC 开着时，每次启动会弹一次授权窗口。
  走计划任务的开机自启不弹。
- **模式编号沿用官方枚举**：0 办公 / 1 均衡 / 2 狂暴 / 3 自定义。自定义模式下有 5 个档位，
  本工具的自定义档位就是这 5 个。
- **风扇转速可能一直显示 `--`**。`System/FanInfo` 的推送在实测中是**间歇性**的 ——
  同一台机器上曾稳定 2 秒一条，也会连着几十分钟一条都不来（重启 `GCUService` 也无效，
  原因未查明）。这是 GCU 后端自己的行为，本工具拿不到就如实显示 `--`，不猜、不缓存旧值。
  上两行限制信息不受影响（走的是 `Fan/Status`，一直正常）。
- 只针对**机械革命 + GCU** 这套后台。换成没有 GCU 的机器，连不上就是连不上。

## 验证过的东西

开发过程中用脚本实测过的行为（`_research/`），改代码时可直接复跑：

- 托盘提示随档位联动，且不含模式名
- 悬浮提示四行拼起来 65~69 个码元，稳在 `szTip` 的 128 上限内（`TestTooltipFitsSzTip`）
- 提示里的三个图标在「提示字体（Microsoft YaHei UI）」下能画出真实字形，不是豆腐块；
  星平面 emoji 的 UTF-16 码元开销也一并钉住（`_emoji_render_check.py`、`TestTipEmojiBudget`）
- 转速行的格式、`--` 占位、缺字段与脏值的处理（`telemetry_test.go`，用的真机报文）
- 右键菜单零延迟弹出（实测 10~27 ms）
- 左键单击 / 双击立刻打开设置界面（5.5 ms）
- 开机自启的开关与保存真的会改写计划任务 / 注册表
- 数据目录不可写时正确回退 `%APPDATA%`，旧配置正确迁移
- 托盘图标在系统里实际渲染为 24×24（宽高差 0），并量化检查留白
